# 交易安全红线

以下是硬性约束，任何课程阶段都不得绕过：

- 默认只读，普通测试命令不得意外执行交易
- 默认 testnet，mainnet 禁止一切写操作
- 交易需显式授权：独立标记 + 写入层运行时二次校验，不能只依赖 `-m` 拦截
- 保持 TLS 验证开启，禁止 `verify=False` 作为默认值
- 所有网络调用必须有连接与读取超时
- 私钥、签名材料、Webhook 不得进入仓库、日志、Allure 附件和对话
- 捕获异常不得把失败转成通过，不得吞断言
- 不使用"上个用例造数据、下个用例消费"的顺序依赖
- 重试按语义区分：只读 POST 与交易 POST 不共用策略
- `rerun` 变绿不算修复
- 清理只处理本次运行可确认归属的资源，禁止清空账户或全仓平掉
- 不压测公开服务，限流与性能实验放本地 Mock
- API wallet（agent）用于签名；账户查询用主账户或子账户地址，不用 agent 地址
